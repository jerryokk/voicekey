## 去 run.cmd 化 + piik 式目录

- 用户环境变量 `CMAKE` = `D:/Program Files\WinPython\python\Lib\site-packages\cmake\data\bin\cmake.exe`，
  cargo 的 cmake 构建脚本原生认这个变量。双向验证过：设了 audiopus_sys 编过、
  不设则 PATH 上 pip 装的坏壳子 `Scripts\cmake.exe` 报 No module named cmake。
  **教训升级：别把真 cmake 加进 PATH**——坏壳子在 PATH 上会抢先，环境变量指定全路径才稳。
- run.cmd 已删；新增 `package.cmd`（ASCII only）→ `dist\VoiceKey\{voicekey.exe, runtime\tunnel\cloudflared.exe}`。
  dist 版实测独立运行：窗口弹出、cloudflared 从自身 runtime\tunnel 加载（与 piik 布局同构）。
- dist/ 在 .gitignore；release 构建带 LTO 约 30 分钟，当前 dist 里放的是 debug exe 供日常双击。

## 彻底移除 cmake（预编译路线）

用户要求"完全没有 cmake"。讨论过纯 Rust 实现 Opus（否：RFC 6716 完整编解码器，
3 万行 C 十几年打磨，重写质量会掉、影响 ASR 识别率）和 cc 现编（可行但没必要），
最终走**预编译**：cargo release profile 让 audiopus_sys 最后编一次 Release 的
opus.lib（946KB，Debug 版路径 out/build/Debug 不可用），vendor 进 crates/opus-sys/lib/。

- crates/opus-sys：手写 7 个 C 函数 FFI（encoder create/ctl/encode/destroy +
  decoder create/decode/destroy，ctl 是 C 可变参数）+ 4 个 ctl 常量 + 往返测试。
- 调用点零改动：core 用 `use opus_sys as ffi` 同名替换。
- 删 .cargo/config.toml、CI choco cmake、用户环境变量 CMAKE。
- 测试踩坑：Opus 有 ~6.5ms 前向延迟，逐点对比必挂；要在重叠范围内找最优滞后对齐。
- 终验：cargo clean 后零 cmake 冷编 1m29s（比之前快——不再编 libopus 源码）；
  vk-test doubao 真云识别与之前一致。
- 直接 cmake 命令行构建会报 No CMAKE_C_COMPILER（cargo/cmake-crate 路径下却成功，
  原因未深究）——重建 opus.lib 走 cargo build --release -p audiopus_sys 最稳。
